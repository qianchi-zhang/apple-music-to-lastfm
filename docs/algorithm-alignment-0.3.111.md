# 记录算法与后台兼容

应用版本为 0.1.0。记录引擎的内部版本号为 0.3.111。

## 固定文件与校验

当前使用的本地 Worker 实现保存在 `apps/worker/production/worker-0.3.111.js`：306567 字节，SHA-256 `531b2090c8a640c059cf0f713c53192099ee3a9da1f25243df39622ada3a2794`。`worker-0.3.106.js` 用于旧版后台的兼容验证。

构建前校验固定摘要，只向生成的运行时追加既有 `loadLedger`、`saveLedger`、`fetchRecentlyPlayed` 导出桥。扩展内附 `algorithm-0.3.111.txt`；编译后的 Worker、实际上传载荷和 ZIP 副本由 `scripts/extension-evidence.ts` 校验一致性。

0.3.111 包含此前 0.3.110 的音频候选过滤、艺术家身份校验、查无结果后的发行回查及历史映射失效；新增地区曲数差异、异体字比较及最终艺术家原生名称保护。

## 保留的适配

Apple 连接验证与开始／恢复基线调用 `fetchRecentlyPlayed`。适配层提供运行故障状态、凭据重验时间及账户队列隔离；切换账户或队列归属冲突时暂停调度。

仍使用当前扩展的默认暂停、同实例串行化、同页 Last.fm 授权和纯查询状态接口。Apple 原曲目封面接口继续独立运行，保留 Workers `manual` 重定向处理、最近十首范围、七天本地 URL 缓存及账户隔离。

## 从 0.3.106 升级

重新加载当前扩展，关闭旧控制台后重新打开，在「设置 → 更新个人后台」或「重新连接 Cloudflare」中验证原部署账户的 Token，然后更新已有后台。升级前旧版健康响应会提示需要更新；上传后必须从健康接口和记录接口分别读回 0.3.111、新固定摘要，并核对既有功能标记，才确认成功。

仅明确的原地更新路径接受本扩展已拥有的 0.3.106 或当前 0.3.111 安装标记，并同时检查安装 ID、账户、服务名、管理密钥绑定、原 KV 和 DO。上传将算法安装标记更新为 0.3.111，其余绑定严格继承。不新建存储、不清除连接、记录或队列；无需再次授权 Apple Music 和 Last.fm。未知版本、其他实例及不一致绑定仍停止更新。新安装和中断安装恢复只接受当前 0.3.111。

构建本地安装包不会自动更新 Cloudflare 实例。用户需先覆盖原扩展加载目录并重新加载，再在扩展内更新已有后台，详见[安装与升级指南](quick-start.md)。

## 验证与边界

固定算法回归共 31 项：原有 26 项加音频过滤、艺术家身份显示、历史映射删除、历史映射复用及地区单曲原生信息 5 项。旧身份缓存断言由 v21 同步为原算法的 v23；所有回归继续禁止真实网络，只使用脱敏公开元数据和明确模拟响应。

应用测试覆盖真实 workerd 中的记录引擎与适配、新旧安装的原地更新、连接及记录流程、Apple 封面和本地缓存。运行 `npm run test:production` 生成 `reports/production-regressions.json`，运行 `npm run package:extension` 生成 `reports/extension-alignment.json`；CI 将当前安装包与摘要作为 artifacts 提供。

自动检查与模拟预览不等同于完整实机验收。发布前已有用户确认更新个人后台后新播放成功记录到 Last.fm；长时间运行、Windows 和完整暂停恢复仍需补充验证。

发布审查修复后，健康接口另有 `recording_diagnostics: true`，状态接口返回固定 `recording_issue` 原因。已有后台更新需同时读回此能力；旧版 0.3.111 没有该字段时，扩展仅为明确的授权失效错误提供兼容提示。账户历史归属由最多 1000 项的独立适配索引记录，不改算法账本或待提交队列；状态及封面 GET 不写账本、不触发采集。
