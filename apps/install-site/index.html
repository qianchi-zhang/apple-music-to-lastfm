01 / 安装完整扩展

先把扩展装进 Chrome

扩展包含完整设置向导：部署 Cloudflare、连接 Apple Music 和 Last.fm、开启记录。所有账户设置都在扩展和对应官方网站完成。

↓ 下载完整扩展

当前为开发预览，未上架商店，需要手动加载一次。macOS 已验证，Windows 尚待实机验证。

1

下载并解压

解压 ZIP，找到包含 manifest.json 的 browser-extension 文件夹。安装后请保留这个文件夹。

2

打开扩展管理页面

在 Chrome 地址栏输入 chrome://extensions，打开右上角的「开发者模式」。

3

加载并打开完整扩展

点击「加载已解压的扩展程序」，选择刚才的文件夹。点击浏览器右上角拼图图标，找到 Apple Music Scrobbler，点击它打开设置页面；也可以固定到工具栏方便下次打开。

找不到文件夹或加载失败？

选择解压后的文件夹，而不是 ZIP；文件夹内应直接包含 manifest.json。若下载来自 GitHub Actions，请先解压外层归档，再解压其中的扩展 ZIP。企业管理的浏览器可能限制安装，需要联系浏览器管理员。

02 / 回到扩展完成设置

接下来的操作，都在扩展里

点击 Chrome 工具栏里的 Apple Music Scrobbler 图标，打开完整扩展。按设置向导完成下面四步；本网页不需要填写任何凭据。

1

部署个人 Cloudflare 后台

使用自己的 Cloudflare 账户，跟随扩展创建临时 API Token，选择账户后部署。扩展会创建个人后台并生成管理钥匙，请按提示备份。不需要 GitHub、npm 或终端。

2

连接 Apple Music

在同一 Chrome 登录 Apple Music 官网，然后回到扩展点击连接并允许所需站点权限。密码只在 Apple 官网输入；不需要 Apple 开发者账户。

3

连接 Last.fm

按扩展引导创建自己的 Last.fm API 应用，把 API Key 和 Shared Secret 填回扩展。打开个人后台完成 Last.fm 官方授权，确认显示的是你要记录到的用户名。

4

开启记录，再播放新歌

在扩展刷新状态，确认账户连接成功后点击「开始自动记录」。等开启成功再正常播放一首新歌。首次开启会建立基线，不会补传已有历史。

Cloudflare 和 Last.fm 需要各自的账户及一次应用设置，不是仅登录 Apple Music 即可完成。遇到错误时，按扩展当前步骤的提示处理。

后台目标检查间隔为 3 分钟，还需等待 Apple 播放历史更新和歌曲识别。关闭网页或扩展页面不影响已开启的后台；以后点扩展图标查看最近记录。

03 / 遇到问题

从出错的那一步继续

先在扩展查看当前步骤和错误文字。不要为了重试反复创建后台、清除扩展数据或切换开始／暂停。

找不到扩展设置页面

点击 Chrome 右上角拼图图标，再点击 Apple Music Scrobbler。如果列表里没有，请回到「安装完整扩展」检查是否加载成功。

返回安装步骤 →
Cloudflare 部署失败或中断

保留原账户和扩展数据，检查 Token 的有效期及扩展要求的权限，再回到同一步继续。若缺少 workers.dev 子域名，先按扩展提示在 Cloudflare 设置。不要反复新建副本；管理钥匙请妥善备份。

Apple Music 找不到账户或连接失效

确认在同一 Chrome 登录了 music.apple.com，保留一个已登录的 Apple Music 标签页，再回扩展重试连接。按 Chrome 提示允许扩展访问 Apple Music 和自己的后台，无需重新部署。

Last.fm 未连接或授权中断

检查应用回调地址、API Key 和 Shared Secret，登录要记录到的 Last.fm 账户。回到个人后台重新点击连接，不要刷新旧授权回调网址。完成后回扩展刷新状态并核对用户名。

播放后还没看到记录

确认扩展显示记录已开启，再播放新歌并等待历史更新及自动检查。点一次「刷新状态」，查看待处理数量和错误文字。若显示待处理，请查看错误原因并等待下一轮检查。结果未确认时先核对 Last.fm，不要盲目重传或反复暂停、开始。

需要反馈问题

提供出错步骤、扩展版本、错误文字和时间，可以附脱敏截图。不要分享 Token、Shared Secret、会话密钥、管理钥匙、凭据文件或完整授权回调网址。
